# KUMA Improved

Модульное расширение для браузера, объединяющее несколько независимых
инструментов для SIEM KUMA.

<img width="346" height="387" alt="image" src="https://github.com/user-attachments/assets/29c215b1-f20a-4643-b91e-bae7d72ba4e6" />

В составе четыре модуля:

| Модуль | Функционал |
|---|---|
| `process-tree` | Перехватывает ответы API событий KUMA и строит граф процессов (4688 / 4689). |
| `web-tester` | Добавляет кнопку в панель переменных правила корреляции и с песочницей функций KUMA. |
| `time-range` | Добавляет в календарь периода событий кнопки расширения на ±5 / 15 / 30 / 60 минут. |
| `sound-alert` | Подписывается на SSE-поток уведомлений KUMA (одно соединение на браузер) и проигрывает alert.mp3 при новом алерте. |

Модули не пересекаются: у каждого своя папка, свой манифест, свои настройки и
свой content-скрипт. Ядро расширения только регистрирует модули на разрешённых
доменах и хранит настройки.

---

## Установка

1. Откройте `chrome://extensions`.
2. Включите «Режим разработчика».
3. Нажмите «Загрузить распакованное расширение» и выберите папку `kuma-extended`.
4. Откройте настройки расширения (иконка → «Все настройки»).
5. Добавьте FQDN вашего KUMA, например `kuma.example.com`.

После добавления домена расширение само до-инжектируется в уже открытые
подходящие вкладки. На уже загруженной странице перехват трафика начнётся
со следующего запроса; для полного перехвата с момента загрузки страницу лучше
перезагрузить.

---

## Как это устроено

```
manifest.json                  точки входа, permissions
background/
  service-worker.js            реестр модулей, настройки, регистрация скриптов
core/
  settings.js                  схема настроек, валидация, match patterns
options/                       страница настроек
popup/                         быстрое меню по иконке
modules/
  registry.json                список установленных модулей
  process-tree/
    module.json                манифест модуля
    content.js                 Изоляция (UI, приём событий)
    inject.js                  MAIN (перехват fetch/XHR)
  web-tester/
    module.json
    tester-core.js             парсер и песочница выражений KUMA
    content.js                 кнопка в панели + окно тестера
  time-range/
    module.json
    content.js                 кнопки расширения периода в календаре событий
  sound-alert/
    module.json
    content.js                 приём SSE-событий и mp3-сигнал (без UI на странице)
    inject.js                  собственное EventSource к /notifications/feed
    alert.mp3                  звук оповещения
docs/
  ADDING_MODULES.md
```

### Настройки

Глобальные:

* "главный тумблер" расширения;
* список целевых FQDN (со схемой и необязательным префиксом пути).

Для каждого модуля:

* Вкл/выкл;
* собственные параметры из `module.json` → `settingsSchema`.

Настройки сохраняются автоматически. Есть экспорт/импорт JSON и сброс.

## Модуль «Песочница функций KUMA»

<img width="677" height="356" alt="image" src="https://github.com/user-attachments/assets/e470115b-21a8-4acf-a862-8260b0942381" />

Кнопка появляется при работе с переменными в селекторе:

```
https://<host>/resources#/resources/correlationRule/<uuid>
```

Некая песочница для проверки функций и переменных. KUMA не позволяет узнать, какой будет результат переменной. 
Расширение решает эту проблему, предоставляя песочницу для работы со встроенными функциями. 

Переменные = некое поле из события KUMA. 
Не указывайте регулярные выражения в переменных, пишите их прямо внутри тестового выражения.

## Модуль «Расширение периода событий»

<img width="372" height="405" alt="image" src="https://github.com/user-attachments/assets/d73fc521-55d2-44ac-bab5-ca65d48aab35" />

В выпадающем календаре периода на странице событий появляется блок
«Расширить период» с кнопками `±5 мин`, `±15 мин`, `±30 мин`, `±1 ч`.

Кнопка:

* вычитает интервал из «Дата от»;
* прибавляет интервал к «Дата до».

Работают только абсолютные значения формата `DD.MM.YYYY HH:mm:ss.SSS`.
Относительные значения (`now`, `now/d`, `now-2d`, `now -2d`) не изменяются:
если оба поля относительные — модуль ничего не меняет. 

После изменения полей нажмите штатную кнопку «Применить». Набор интервалов
настраивается в параметрах модуля (список минут через запятую).

## Модуль «Звуковое оповещение»

Модуль **не перехватывает и не повторяет запросы KUMA**. Он подписывается на
поток уведомлений KUMA (Server-Sent Events) отдельным соединением:

```
GET /api/private/notifications/feed
event: notification
data: {"kind":"alert","payload":{"id":"…","name":"…"}}
```

### Одно соединение на браузер

Веб-интерфейс KUMA держит поток только в одной вкладке-лидере. Модуль делает
так же: вкладки договариваются через `BroadcastChannel`, и поток открывает
**только одна вкладка KUMA** — остальные не создают лишней нагрузки на сервер.

* вкладка с наименьшим идентификатором становится ведущей;
* если ведущая вкладка закрылась, поток поднимает следующая;
* звук играет **только в ведущей вкладке**, остальные вкладки молчат;
* соединение открывается не сразу, а через 0,2 с после старта: за это время
  вкладка узнаёт о соседях и, если уступает, к серверу не обращается.

Каждое событие `kind = "alert"` проигрывает сигнал из
`modules/sound-alert/alert.mp3` (байты грузятся один раз, буфер декодируется и
кэшируется).

* На странице KUMA **никакого UI нет**: модуль не рисует плашки, кнопки и
  индикаторы — только звук.
* Выключается звук через меню расширения: тумблер модуля «Звуковое
  оповещение» или главный тумблер расширения — отдельной кнопки на странице
  нет.

Повтор того же алерта (по `payload.id`) не звенит второй раз — это защищает от
дублей при переподключении потока.

Чтобы заменить сигнал, положите свой mp3 под именем `alert.mp3` в папку
модуля и обновите расширение на `chrome://extensions`.

### Подключение и обрывы

* Если KUMA закрывает поток (истекла сессия, перезапуск), модуль
  переподключается сам: через 2 секунды, затем с удвоением до 60 секунд.
  После успешного подключения пауза снова 2 секунды.
* Звук звучит только в ведущей вкладке; остальные вкладки KUMA поток не
  открывают и молчат.

Первое взаимодействие со страницей (клик или нажатие клавиши) «разблокирует»
звук: `AudioContext` создаётся **только внутри обработчика этого жеста**,
иначе Chrome блокирует автозапуск и пишет в консоль
«The AudioContext was not allowed to start». До первого клика по странице
сигнал не прозвучит.

### Параметры модуля

* **Путь потока уведомлений** — по умолчанию `/api/private/notifications/feed`.
  Адрес принудительно приводится к текущему origin: чужой хост в настройках
  не должен получить куки KUMA;
* **Громкость** — 0–100 %, по умолчанию 70.

### Особенности

* `EventSource` не проходит через `fetch`/`XMLHttpRequest`, поэтому в
  Network такой поток виден как тип `eventsource` со статусом `pending`,
  который никогда не завершается. В HAR он тоже не попадает.
* Чтобы звук был всегда, оставьте хотя бы одну вкладку KUMA открытой —
  звучит та, которая ведёт поток.
* Подробный разбор потока — в `docs/KUMA_ALERT_NOTIFICATIONS.md`.

# Модуль «Process Tree»

<img width="1718" height="838" alt="image" src="https://github.com/user-attachments/assets/f6f56738-70b8-4370-b5d7-f9d5f2e24f4d" />

Отрисовывает граф создания процессов по событиям 4688 на основе Parent Process ID и Created Process ID. 
Модуль можно вызвать при работе с вкладкой "события" и наличии событий 4688 при выборке. 
Ищите кнопку справа снизу. 

## Ограничения

* Динамическая регистрация скриптов не действует на уже открытые вкладки.
  Расширение до-инжектирует модули после сохранения настроек, но перехват
  трафика «с самого начала» гарантируется только после перезагрузки страницы.
* Content-скрипты работают в изолированной среде. `inject.js` модуля
  `process-tree` добавляется в MAIN-среду через `<script>` и
  `web_accessible_resources`.
* Для работы на домене нужны host-permissions. Сейчас запрошены `<all_urls>`,
  а фактическое применение ограничено списком FQDN на уровне регистрации.
