# KUMA Improved

Модульное расширение для браузера, объединяющее несколько независимых
инструментов для SIEM KUMA.

<img width="349" height="440" alt="image" src="https://github.com/user-attachments/assets/403726fc-e16f-463f-a927-ad831084d4e9" />


В составе четыре модуля:

| Модуль | Функционал |
|---|---|
| `process-tree` | Строит граф процессов (4688 / 4689). |
| `web-tester` | Добавляет песочницу функций(в правила корреляции) KUMA. |
| `time-range` | Добавляет в календарь периода событий кнопки на ±5 / 15 / 30 / 60 минут. |
| `sound-alert` | Проигрывает звук при новом алерте. |
| `ui-improve` | Компактные таблица событий и панель события на странице «События». |

Модули не пересекаются: у каждого своя папка, свой манифест, свои настройки и
свой content-скрипт. Ядро расширения только регистрирует модули на разрешённых
доменах и хранит настройки.

---

## Установка

1. Откройте `chrome://extensions`.
2. Включите «Режим разработчика».
3. Нажмите «Загрузить распакованное расширение» и выберите папку `kuma-improved`.
4. Откройте настройки расширения (иконка → «Все настройки»).
5. Добавьте FQDN вашего KUMA, например `kuma.example.com`.

После добавления домена расширение само до-инжектируется в уже открытые
подходящие вкладки. На уже загруженной странице перехват трафика начнётся
со следующего запроса; для полного перехвата с момента загрузки страницу лучше
перезагрузить.

## Как это устроено

```
manifest.json                  точки входа, permissions
background/
  service-worker.js            реестр модулей, настройки, регистрация скриптов
core/
  settings.js                  схема настроек, валидация, match patterns
options/                       страница настроек
popup/                         быстрое меню по иконке
modules/
  registry.json                список установленных модулей
  process-tree/
    module.json                манифест модуля
    content.js                 Изоляция (UI, приём событий)
    inject.js                  MAIN (перехват fetch/XHR)
  web-tester/
    module.json
    tester-core.js             парсер и песочница выражений KUMA
    content.js                 кнопка в панели + окно тестера
  time-range/
    module.json
    content.js                 кнопки расширения периода в календаре событий
  sound-alert/
    module.json
    content.js                 приём SSE-событий и mp3-сигнал (без UI на странице)
    inject.js                  собственное EventSource к /notifications/feed
    alert.mp3                  звук оповещения
  ui-improve/
    module.json
    content.js                 плотные таблица событий и панель события
docs/
  ADDING_MODULES.md
```

### Настройки

Глобальные:

* "главный тумблер" расширения;
* список целевых FQDN (со схемой и необязательным префиксом пути).

Для каждого модуля:

* Вкл/выкл;
* собственные параметры из `module.json` → `settingsSchema`.

Настройки сохраняются автоматически. Есть экспорт/импорт JSON и сброс.

## Модуль «Песочница функций KUMA»

<img width="677" height="356" alt="image" src="https://github.com/user-attachments/assets/e470115b-21a8-4acf-a862-8260b0942381" />

Кнопка появляется при работе с переменными в селекторе:

```
https://<host>/resources#/resources/correlationRule/<uuid>
```

Некая песочница для проверки функций и переменных. KUMA не позволяет узнать, какой будет результат переменной. 
Расширение решает эту проблему, предоставляя песочницу для работы со встроенными функциями. 

Окно открывается пустым. Введённое запоминается только на время сессии
страницы: закрыть и снова открыть — данные на месте, но после перезагрузки
страницы или на другой странице окно снова пустое.

Кнопка **«Перенести переменные»** копирует переменные текущего правила из
панели KUMA в песочницу (существующие с тем же именем обновляются).

Переменные = некое поле из события KUMA. 
Не указывайте регулярные выражения в переменных, пишите их прямо внутри тестового выражения. 

Значение переменной может быть и выражением — как в рабочей области KUMA:

```
SourceUserName  domain@local.domain
my_var2026      substring(SourceUserName, last_index_of('@', SourceUserName) + 1)
```

В «Выражение» пишем `my_var2026` — песочница вычислит `local.domain`.

**Всё пишется без `$`**, как в KUMA:

* стандартные поля KUMA (`SourceUserName`, `DeviceCustomString1`, `SourceAddress`
  и остальные из списка интерфейса) — пишутся без `$` и подставляются из окна
  «Значения переменных»; если значения нет, поле считается полем события (пусто);
* любые другие имена, заданные в окне, — тоже без `$`
  (`len(my_var2026)`, `to_upper(my_var2026)`);
* имя, которого нет ни в списке полей KUMA, ни в окне, — обычная строка
  (`len(abcd)` → 4).

Синтаксис с `$` (`$my_var2026`) по-прежнему принимается для совместимости.
Если значение не является корректным выражением, оно используется как строка
(`domain@local.domain`, `admin`). Переменные могут ссылаться друг на друга.
Галочка «Считать значения переменных выражениями» отключает это поведение.

Условия в `conditional` можно писать как с обратными кавычками, так и с
обычными (по образцу SQL):

```
conditional(`my_var2026 LIKE '-.*'`, 'false', 'true')
conditional(my_var2026 LIKE '.*', 'true', 'false')
```

Сравнение идёт по регулярному выражению (как `regexp_match` в KUMA), поэтому
`-.*` совпадает с `-admin`, а `.` не совпадает с ведущим `-`. Ограничения вида
`$event.UserName.IsNotWhitespace()` игнорируются.
Список «Как вычислены переменные» под результатом показывает, во что
превратилась каждая переменная.

## Модуль «Время событий ±»

<img width="372" height="405" alt="image" src="https://github.com/user-attachments/assets/d73fc521-55d2-44ac-bab5-ca65d48aab35" />

В выпадающем календаре периода на странице событий появляется блок
«Расширить период» с кнопками `±5 мин`, `±15 мин`, `±30 мин`, `±1 ч`.

Кнопка:

* вычитает интервал из «Дата от»;
* прибавляет интервал к «Дата до».

Работают только абсолютные значения формата `DD.MM.YYYY HH:mm:ss.SSS`.
Относительные значения (`now`, `now/d`, `now-2d`, `now -2d`) не изменяются:
если оба поля относительные — модуль ничего не меняет. 

После изменения полей нажмите штатную кнопку «Применить». Набор интервалов
настраивается в параметрах модуля (список минут через запятую).

## Модуль «Звуковое оповещение»

Воспроизводит звук, при создании нового алерта в KUMA.

Модуль подписывается на
поток уведомлений KUMA (Server-Sent Events) отдельным соединением:

```
GET /api/private/notifications/feed
event: notification
data: {"kind":"alert","payload":{"id":"…","name":"…"}}
```

Этот самый механизм выводит уведомление в UI KUMA если в настройках профиля включить
"Уведомлять об алертах в WEB интерфейсе"

### Параметры модуля

* **Путь потока уведомлений** — по умолчанию `/api/private/notifications/feed`.
  Адрес принудительно приводится к текущему origin: чужой хост в настройках
  не должен получить куки KUMA;
* **Громкость** — 0–100 %, по умолчанию 70.
* **Заменить звуковой сигнал** - положите свой mp3 под именем `alert.mp3` в папку
  модуля и обновите расширение на `chrome://extensions`.

### Особенности

* `EventSource` не проходит через `fetch`/`XMLHttpRequest`, поэтому в
  Network такой поток виден как тип `eventsource` со статусом `pending`,
  который никогда не завершается. В HAR он тоже не попадает.
* Чтобы звук был всегда, оставьте хотя бы одну вкладку KUMA открытой —
  звучит та, которая ведёт поток.
* Подробный разбор потока — в `docs/KUMA_ALERT_NOTIFICATIONS.md`.

## Модуль «UI Improve — компактная таблица событий»

Делает таблицу результатов на странице «События» (`/threat-hunting`) плотнее:

* строки и шапка — 24 px вместо 40;
* шрифт — 12 px вместо 14;
* отступы в ячейках — 2 × 6 px вместо 10 × 12 px;
* вертикальные линии-разделители между столбцами (раньше были только
  горизонтальные);
* столбцы сужаются по фактическому содержимому (по длине заголовка и
  значений) так, чтобы на экране помещалось больше данных; самый длинный
  столбец забирает оставшуюся ширину.

Верхняя часть страницы тоже сжимается:

* заголовок «События» — 18 px вместо 28;
* шрифт запроса — 11 px вместо 12, подсказка «Ctrl + Enter» скрыта, кнопки
  панели запроса и строка «Результаты запроса» компактнее. Само поле запроса
  (рамка, ручка ресайза, высота) и кнопки остаются штатными;
* кнопки и селекты в шапке страницы (автообновление, период, тенанты) —
  22 px вместо 32, шрифт 12 px вместо 14, иконки 13 px, чипы тенантов 14 px;
  всё следует за настройкой «Заголовок „События“», чтобы на маленьком экране
  шапка оставалась низкой.

Таблица занимает остаток окна (примерно 2/3 высоты) вместо фиксированных
338 px; пересчитывается при изменении размера окна.

Панель «Информация о событии», которая открывается по клику на строку, тоже
становится компактной таблицей:

* ширина панели — 600 px вместо ~800 (вся оставшаяся часть окна);
* поля идут строками по 22 px со шрифтом 12 px вместо 14;
* колонка с названием поля отделена вертикальной линией и залита светло-серым,
  строки разделены горизонтальными линиями, чётные строки подсвечены;
* кнопки копирования появляются при наведении справа и не отнимают ширину
  у значения;
* строка «Копировать» сверху — кнопка 24 px вместо 32, шрифт 12 px;
* блок «Исходное событие» — заголовок 15 px вместо 24, кнопка копирования
  26 px вместо 32, само событие — моноширинный блок 12 px с прокруткой
  (не выше 260 px).

Всё применяется только к странице «События»: другие разделы KUMA, а также
модальные окна и выпадающие списки не меняются.

Если вручную потянуть границу столбца, ширина запоминается и удерживается —
в том числе когда KUMA перерисовывает таблицу при догрузке событий и смене
выборки. Живёт до перезагрузки страницы.

**Двойной клик по границе столбца** — ширина по тексту: столбец сжимается до
самого длинного значения (или заголовка, если он длиннее). В отличие от
подгонки под всё окно, здесь меняется один столбец, остальные не трогаются.

**Shift + двойной клик по границе** — сброс: все ручные ширины забываются,
таблица возвращается к компактной автоподгонке.

Ширины, закреплённые перетаскиванием или двойным кликом, удерживаются даже
когда KUMA перерисовывает таблицу: при догрузке событий прокруткой до конца,
смене выборки или фильтра. Шапка и строки таблицы в KUMA — две отдельные
таблицы, модуль держит их в одинаковом размере.

### Параметры модуля

* **Включить компактную таблицу** — главный выключатель модуля;
* **Сжать размер шапки** — компактная верхняя часть страницы и таблица
  на остаток окна (вместо фиксированных 338 px);
* **Заголовок «События», px**, **Шрифт запроса, px** — размеры верхней части;
* **Компактная панель события** — включать/выключать табличное оформление
  панели «Информация о событии»;
* **Ширина панели события, px** — по умолчанию 600;
* **Высота строки / шапки, px**;
* **Размер шрифта, px**;
* **Горизонтальный / вертикальный отступ ячейки, px**.

# Модуль «Process Tree»

<img width="1718" height="838" alt="image" src="https://github.com/user-attachments/assets/f6f56738-70b8-4370-b5d7-f9d5f2e24f4d" />

Отрисовывает граф создания процессов по событиям 4688 на основе Parent Process ID и Created Process ID. 
Модуль можно вызвать при работе с вкладкой "события" и наличии событий 4688 при выборке. 
Ищите кнопку справа снизу. 

## Ограничения

* Динамическая регистрация скриптов не действует на уже открытые вкладки.
  Расширение до-инжектирует модули после сохранения настроек, но перехват
  трафика «с самого начала» гарантируется только после перезагрузки страницы.
* Content-скрипты работают в изолированной среде. `inject.js` модуля
  `process-tree` добавляется в MAIN-среду через `<script>` и
  `web_accessible_resources`.
* Для работы на домене нужны host-permissions. Сейчас запрошены `<all_urls>`,
  а фактическое применение ограничено списком FQDN на уровне регистрации.
